# Dialife live platform

The dedicated Dialife Supabase project now contains 34 application tables.
Authenticated dashboard pages use the same approved design and load real,
permission-filtered records. Unauthenticated visitors see the fictional preview.
The public preview never requests private dashboard records.

## Connected areas

| Area          | Records                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------- |
| Admissions    | Candidate applications, user accounts and candidate profiles                                  |
| Learning      | Programs, modules, lessons, progress, cohorts, enrollments and trainer assignments            |
| Teaching      | Sessions, attendance, assessments, submissions, grades and feedback                           |
| Certification | Certificates linked to completed enrollments                                                  |
| Recruitment   | Employer organizations, team memberships, staffing requests, candidate matches and interviews |
| VA work       | Placements, tasks, work schedules and timesheets                                              |
| Operations    | Calendar events, notifications, activity history, support tickets and replies                 |
| Documents     | Owner-scoped files, metadata and short-lived signed downloads                                 |
| Simulations   | Synthetic scenarios, practice transcripts, uploaded recordings and trainer evaluations        |

Voice-agent calling and automated AI scoring are separate provider integrations;
this release stores and connects practice records and human evaluations. It does
not claim that an external voice provider has been connected.

## Account access

- Sign in or create an account at `/login`.
- New accounts receive the applicant role, regardless of any client-provided role.
- Email verification is required for live access.
- The approved owner address `Admin@dialifeva.com` receives administrator access
  only after Supabase confirms that email. No password is preconfigured or stored
  in application source.
- Administrators assign trainer, employer and Medical VA roles in User Accounts,
  then link trainers to cohorts and employers to organizations.
- Account role changes are checked from the database on each private API request.
- `?mode=demo` explicitly selects the fictional preview for a signed-in user.

## Initial operational setup

1. Verify the owner account, then sign in.
2. Create a program, its modules and lessons; publish the ready content.
3. Create a cohort and enroll registered applicants. Assign its trainer.
4. Schedule sessions, record attendance, set assessments and review submissions.
5. Mark completed enrollments and issue their certificates.
6. Create employer organizations and link verified employer accounts.
7. Create staffing requests, match candidates and schedule interviews.
8. Assign a Medical VA to a placement, then create tasks and shifts. VAs submit
   time entries; employer staff review them.

The module directory exposes the sections available to the signed-in role.
Forms save immediately, lists are paginated and searchable, and exports include
only the records visible on the current page. Dashboard reports use live totals.

## Authentication URL configuration

The Supabase Auth Site URL should be `https://dialife-medical-va.vercel.app`.
Allowed redirects should include these explicit URLs:

- `https://dialife-medical-va.vercel.app/auth/callback`
- `https://dialife-medical-va.vercel.app/auth/callback?next=/login?recovery=1`
- The corresponding trusted development callback when local sign-up is required.

The application handles PKCE callbacks and token confirmation, password reset,
session refresh and sign-out. No client-controlled redirect can send the callback
to an arbitrary destination.

## Access controls

- All 34 application tables have row level security; anonymous SELECT is denied.
- Anonymous intake is restricted to its original safe input columns.
- Trainees access their own records and enrolled cohorts.
- Trainers access assigned cohorts and their learners' assessments.
- Employer access follows explicit organization memberships and request ownership.
- Medical VAs access their own placements, tasks and time entries.
- Privileged authorization helpers return booleans and live in an unexposed schema.
- Protected columns cannot be changed through a direct REST request to bypass UI rules.
- Audit history is generated by database triggers and cannot be forged by clients.
- File storage is private, owner-scoped, limited to supported formats and 10 MB,
  and accessed through five-minute signed URLs after authorization.
- Browser and server clients use the publishable key and the user's session.
  No service-role or management key is required by the deployed application.

## Database changes and checks

`supabase/migrations/20261108172042_live_platform.sql` extends the seven original
Dialife tables; it is an incremental migration for the existing project.
`20261108201924_shared_staff_edits.sql` permits assigned colleagues to edit shared
records while retaining their original creator.
`20261108203249_insert_visibility.sql` keeps employer request and support-ticket
creation compatible with RLS-protected insert responses.

`tests/platform-rls.sql` creates synthetic fixtures in a transaction and rolls them
back. Its 45 checks cover row isolation, role escalation, grading, timesheet
approval, cohort capacity, private records and anonymous intake.

`tests/platform-http.mjs` exercises authenticated API workflows with disposable
verified test identities supplied outside the repository. It requires a test
fixture path and never sends invitation or verification emails. No test password
or token belongs in git. `tests/run-http.mjs` starts a production-build server
for these HTTP checks and stops it afterward.
